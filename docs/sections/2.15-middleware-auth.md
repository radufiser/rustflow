# 2.15 - Simple Header-Based Auth with Middleware

## Overview

In 2.14 we added API key authentication using a custom extractor. It works — but look at the cost. Every mutation handler across three files gained `_auth: RequireApiKey` as a parameter:

```rust
// tasks.rs — 4 handlers touched
async fn create(_auth: RequireApiKey, ...) -> ...
async fn delete(_auth: RequireApiKey, ...) -> ...
async fn update(_auth: RequireApiKey, ...) -> ...
async fn change_status(_auth: RequireApiKey, ...) -> ...

// projects.rs — 2 handlers touched
async fn create(_auth: RequireApiKey, ...) -> ...
async fn delete(_auth: RequireApiKey, ...) -> ...

// users.rs — 2 handlers touched
async fn create(_auth: RequireApiKey, ...) -> ...
async fn delete(_auth: RequireApiKey, ...) -> ...
```

Eight handlers, eight identical parameters, and every new mutation handler requires remembering to add it. Forget once and you have a silent security hole — the endpoint works, passes all functional tests, and is completely unprotected.

In this lesson we **refactor authentication into a Tower middleware layer**. Instead of each handler checking credentials, the middleware intercepts every request _before_ it reaches any handler. We apply it at the **router level**, not the handler level — one line of code protects an entire group of routes.

### Before and After

```text
2.14 (extractor approach):
  create(_auth: RequireApiKey, ...)    ← each handler checks auth
  delete(_auth: RequireApiKey, ...)    ← each handler checks auth
  update(_auth: RequireApiKey, ...)    ← each handler checks auth

2.15 (middleware approach):
  Router::new()
    .route("/", post(create))          ← handlers are clean
    .route("/{id}", put(update).delete(delete))
    .layer(middleware::from_fn(require_api_key))   ← one line protects all
```

The handlers lose their auth parameter entirely — they go back to being pure business logic. Protection moves to the routing layer where it's visible, centralized, and impossible to forget.

## Extractors vs Middleware: When to Use Which

Both extractors and middleware intercept requests before your handler runs. The difference is _scope_:

| Aspect | Extractor (2.14) | Middleware (2.15) |
|---|---|---|
| **Applied to** | One handler at a time | All routes in a router/group |
| **Opt-in model** | Each handler adds the parameter | Routes are protected by position |
| **Forgetting it** | Silent security hole | Impossible — middleware covers all routes |
| **Handler awareness** | Handler knows auth happened (`_auth` param) | Handler doesn't know (middleware is invisible) |
| **Granularity** | Per-handler | Per-router (we'll refine in 2.17) |
| **Best for** | Optional per-handler checks, extracting data | Blanket policies (auth, logging, rate limiting) |

Neither is universally better. Extractors are better when different handlers need different auth logic (admin vs user). Middleware is better when the same policy applies to many routes — which is our case.

## How Tower Middleware Works

Recall from 2.13 that Tower has two core concepts: **Services** (do work) and **Layers** (wrap services to add behavior). Middleware is just a Layer that runs code before and/or after the inner Service:

```text
Request → [ Middleware ] → [ Handler ]
                │                │
                ├── before:      │
                │   check auth   │
                │   log request  │
                │                ├── handler runs
                ├── after:       │
                │   add headers  │
                │   log response │
                │                │
Response ← [ Middleware ] ← [ Handler ]
```

Axum provides `axum::middleware::from_fn` — a convenient way to write middleware as a plain async function rather than implementing the Tower `Service` trait by hand. The function receives the request and a `Next` handle to call the inner service:

```rust
async fn my_middleware(
    request: Request,
    next: Next,
) -> Response {
    // Before: inspect or modify the request
    println!("Incoming: {} {}", request.method(), request.uri());

    // Call the next service (handler or next middleware)
    let response = next.run(request).await;

    // After: inspect or modify the response
    println!("Outgoing: {}", response.status());

    response
}
```

The `Next` type is Axum's handle to the rest of the middleware stack plus the final handler. Calling `next.run(request)` passes the request downstream. If you _don't_ call `next.run()`, the request never reaches the handler — that's how auth middleware rejects requests.

### The Critical Insight: Early Return

Auth middleware rejects by returning a response _without_ calling `next.run()`:

```rust
async fn require_api_key(request: Request, next: Next) -> Response {
    // Check the header
    let is_valid = request.headers()
        .get("x-api-key")
        .and_then(|v| v.to_str().ok())
        .map_or(false, |key| key == API_KEY);

    if !is_valid {
        // Return error response — handler never runs
        return RustFlowError::Unauthorized("...".into()).into_response();
    }

    // Valid — continue to the handler
    next.run(request).await
}
```

This is functionally identical to the extractor returning `Err(RustFlowError::Unauthorized(...))` — but now it's one function protecting all routes in its scope.

## Step 1: Create the Auth Middleware

**Create** `crates/rustflow-server/src/routes/middleware.rs`:

```rust name=crates/rustflow-server/src/routes/middleware.rs
use axum::{
    extract::Request,
    middleware::Next,
    response::Response,
};
use rustflow_common::API_KEY;
use crate::errors::RustFlowError;
use axum::response::IntoResponse;

/// Middleware that validates the `x-api-key` header on every request
/// it wraps.
///
/// Applied to a router with:
/// ```ignore
/// Router::new()
///     .route("/", post(create))
///     .layer(axum::middleware::from_fn(require_api_key))
/// ```
///
/// Requests without a valid key receive `401 Unauthorized` and never
/// reach the handler.
pub async fn require_api_key(request: Request, next: Next) -> Response {
    let api_key = request
        .headers()
        .get("x-api-key")
        .and_then(|value| value.to_str().ok());

    match api_key {
        Some(key) if key == API_KEY => next.run(request).await,
        Some(_) => RustFlowError::Forbidden("Invalid API key".into()).into_response(),
        None => RustFlowError::Unauthorized("Missing x-api-key header".into()).into_response(),
    }
}
```

### Anatomy of the Middleware

Let's walk through every piece:

**The signature:**

```rust
pub async fn require_api_key(request: Request, next: Next) -> Response {
```

- `request: Request` — the full incoming HTTP request (method, URI, headers, body)
- `next: Next` — a handle to call the next layer/handler in the stack
- `-> Response` — returns a concrete response (not `Result` — middleware must always produce a response)

**The validation logic** is identical to the extractor from 2.14 — read the header, compare to the known key. The only difference is the return type:

```rust
// 2.14 extractor: returns Result — Axum calls IntoResponse on the Err
Err(RustFlowError::Unauthorized("...".into()))

// 2.15 middleware: calls IntoResponse directly — returns Response
RustFlowError::Unauthorized("...".into()).into_response()
```

**The happy path** — `next.run(request).await` passes the request to the handler (or next middleware). The response flows back through us, and we return it unmodified. This is "pass-through" middleware — it only inspects on the way in.

**No `&self`, no state** — `from_fn` middleware is a plain function, not a struct. This keeps it simple. If you needed access to `AppState`, you'd use `from_fn_with_state` instead (we'll do this in 2.16).

### Why a Separate Module?

Middleware is neither a handler nor an extractor — it's infrastructure that sits between routing and handlers. Placing it in `routes/middleware.rs` keeps it close to the routers that use it while separating it from business logic. As you add more middleware (logging, rate limiting, CORS), they'll all live here.

use axum::{
    extract::{
        rejection::JsonRejection, rejection::QueryRejection, FromRequest, FromRequestParts, Query,
        Request,
    },
    http::request::Parts,
    http::StatusCode,
    response::{IntoResponse, Response},
    Json,
};
use serde::de::DeserializeOwned;
use validator::Validate;

// ── Validated JSON Extractor ────────────────────────────────

pub struct ValidatedJson<T>(pub T);

pub enum ValidatedJsonError {
    JsonError(JsonRejection),
    ValidationError(validator::ValidationErrors),
}

impl IntoResponse for ValidatedJsonError {
    fn into_response(self) -> Response {
        match self {
            Self::JsonError(rejection) => {
                let body = serde_json::json!({
                    "error": "Invalid JSON",
                    "details": rejection.body_text(),
                });
                (rejection.status(), Json(body)).into_response()
            }
            Self::ValidationError(errors) => {
                let body = serde_json::json!({
                    "error": "Validation failed",
                    "details": errors.field_errors().iter().map(|(field, errs)| {
                        (field.to_string(), errs.iter().filter_map(|e| {
                            e.message.as_ref().map(|m| m.to_string())
                        }).collect::<Vec<_>>())
                    }).collect::<std::collections::HashMap<_, _>>()
                });
                (StatusCode::UNPROCESSABLE_ENTITY, Json(body)).into_response()
            }
        }
    }
}

impl<T, S> FromRequest<S> for ValidatedJson<T>
where
    T: DeserializeOwned + Validate,
    S: Send + Sync,
{
    type Rejection = ValidatedJsonError;

    async fn from_request(req: Request, state: &S) -> Result<Self, Self::Rejection> {
        let Json(value) = Json::<T>::from_request(req, state)
            .await
            .map_err(ValidatedJsonError::JsonError)?;
        value
            .validate()
            .map_err(ValidatedJsonError::ValidationError)?;

        Ok(ValidatedJson(value))
    }
}

// ── Validated Query Extractor ───────────────────────────────

pub struct ValidatedQuery<T>(pub T);

pub enum ValidatedQueryError {
    QueryError(QueryRejection),
    ValidationError(validator::ValidationErrors),
}

impl IntoResponse for ValidatedQueryError {
    fn into_response(self) -> Response {
        match self {
            Self::QueryError(rejection) => {
                let body = serde_json::json!({
                    "error": "Invalid query string",
                    "details": rejection.body_text(),
                });
                (rejection.status(), Json(body)).into_response()
            }
            Self::ValidationError(errors) => {
                let body = serde_json::json!({
                    "error": "Validation failed",
                    "details": errors.field_errors().iter().map(|(field, errs)| {
                        (field.to_string(), errs.iter().filter_map(|e| {
                            e.message.as_ref().map(|m| m.to_string())
                        }).collect::<Vec<_>>())
                    }).collect::<std::collections::HashMap<_, _>>()
                });
                (StatusCode::UNPROCESSABLE_ENTITY, Json(body)).into_response()
            }
        }
    }
}

impl<T, S> FromRequestParts<S> for ValidatedQuery<T>
where
    T: DeserializeOwned + Validate,
    S: Send + Sync,
{
    type Rejection = ValidatedQueryError;

    async fn from_request_parts(parts: &mut Parts, state: &S) -> Result<Self, Self::Rejection> {
        let Query(value) = Query::<T>::from_request_parts(parts, state)
            .await
            .map_err(ValidatedQueryError::QueryError)?;
        value
            .validate()
            .map_err(ValidatedQueryError::ValidationError)?;

        Ok(ValidatedQuery(value))
    }
}
```

## Step 4: Refactor Task Routes

**Update** `crates/rustflow-server/src/routes/tasks.rs` — remove `_auth: RequireApiKey` from every handler and apply the middleware to the router.

Changes:
- Remove `use crate::extractors::RequireApiKey;` — replace with `use crate::routes::middleware::require_api_key;`
- Remove `_auth: RequireApiKey` from `create`, `delete`, `update`, `change_status`

```rust name=crates/rustflow-server/src/routes/tasks.rs
use crate::errors::RustFlowError;
use crate::extractors::{ValidatedJson, ValidatedQuery};
use crate::routes::middleware::require_api_key;
use crate::state::AppState;
use axum::extract::{Path, State};
use axum::http::StatusCode;
use axum::routing::{get, patch};
use axum::{middleware, Json, Router};
use rustflow_common::{CreateTask, Task, TaskFilter, TaskStatus};

/// GET /tasks?status=pending&priority=high
///
/// No auth required — reading tasks is a public operation.
async fn list(
    State(state): State<AppState>,
    ValidatedQuery(filter): ValidatedQuery<TaskFilter>,
) -> Json<Vec<Task>> {
    let state = state.tasks.0.read().await;

    let filtered: Vec<Task> = state
        .tasks
        .iter()
        .filter(|task| filter.status.as_ref().map_or(true, |s| &task.status == s))
        .filter(|task| filter.priority.as_ref().map_or(true, |p| &task.priority == p))
        .filter(|task| {
            filter.search.as_ref().map_or(true, |s| {
                task.title.contains(s)
                    || task.description.as_ref().map_or(false, |d| d.contains(s))
            })
        })
        .cloned()
        .collect();

    Json(filtered)
}

/// GET /tasks/:id
///
/// No auth required.
async fn get_one(
    State(state): State<AppState>,
    Path(id): Path<u64>,
) -> Result<Json<Task>, RustFlowError> {
    let store = state.tasks.0.read().await;

    store
        .tasks
        .iter()
        .find(|task| task.id == id)
        .cloned()
        .map(Json)
        .ok_or(RustFlowError::NotFound(format!(
            "Task with id {} does not exist",
            id
        )))
}

/// POST /tasks
///
/// Auth enforced by router-level middleware — handler is clean.
async fn create(
    State(state): State<AppState>,
    ValidatedJson(payload): ValidatedJson<CreateTask>,
) -> Result<(StatusCode, Json<Task>), RustFlowError> {
    let mut store = state.tasks.0.write().await;

    if store.tasks.iter().any(|x| payload.title == x.title) {
        return Err(RustFlowError::Conflict(format!(
            "Task with title {} already exists",
            payload.title
        )));
    }

    let task = Task {
        id: store.next_id,
        title: payload.title,
        description: payload.description,
        priority: payload.priority,
        status: TaskStatus::Pending,
    };

    store.next_id += 1;
    store.tasks.push(task.clone());

    Ok((StatusCode::CREATED, Json(task)))
}

/// DELETE /tasks/:id
async fn delete(
    State(state): State<AppState>,
    Path(id): Path<u64>,
) -> Result<StatusCode, RustFlowError> {
    let mut store = state.tasks.0.write().await;
    let len_before = store.tasks.len();

    store.tasks.retain(|task| task.id != id);

    if store.tasks.len() < len_before {
        Ok(StatusCode::NO_CONTENT)
    } else {
        Err(RustFlowError::NotFound(format!(
            "Task with id {id} does not exist"
        )))
    }
}

/// PUT /tasks/:id
async fn update(
    State(state): State<AppState>,
    Path(id): Path<u64>,
    ValidatedJson(payload): ValidatedJson<CreateTask>,
) -> Result<Json<Task>, RustFlowError> {
    let mut store = state.tasks.0.write().await;

    if let Some(task) = store.tasks.iter_mut().find(|task| task.id == id) {
        task.title = payload.title;
        task.description = payload.description;
        task.priority = payload.priority;
        Ok(Json(task.clone()))
    } else {
        Err(RustFlowError::NotFound(format!(
            "Task with id {} does not exist",
            id
        )))
    }
}

/// PATCH /tasks/:id/status
async fn change_status(
    State(state): State<AppState>,
    Path(id): Path<u64>,
    Json(payload): Json<TaskStatus>,
) -> Result<Json<Task>, RustFlowError> {
    let mut store = state.tasks.0.write().await;

    if let Some(task) = store.tasks.iter_mut().find(|task| task.id == id) {
        task.status = payload;
        Ok(Json(task.clone()))
    } else {
        Err(RustFlowError::NotFound(format!(
            "Task with id {} does not exist",
            id
        )))
    }
}

pub fn router() -> Router<AppState> {
    Router::new()
        .route("/", get(list).post(create))
        .route("/{id}", get(get_one).put(update).delete(delete))
        .route("/{id}/status", patch(change_status))
        .layer(middleware::from_fn(require_api_key))
}
```

### Wait — The Middleware Protects ALL Routes, Including GETs!

Yes! This is an important observation. The `.layer()` call applies `require_api_key` to **every route** in this router — including `GET /api/tasks` (list) and `GET /api/tasks/:id` (get_one).

This means that after this lesson, even reading tasks requires an API key. That's a regression from 2.14, where reads were open.

**This is intentional.** We want you to feel this problem before we solve it in 2.17 (Selectively Applying Layers). For now, the entire task router is protected. The fix — splitting read and write routes into separate routers with different middleware — is a fundamental pattern that deserves its own lesson.

## How `.layer()` Wrapping Works

Understanding `.layer()` position is critical. In Axum, **`.layer()` wraps everything _above_ it in the chain**:

```rust
Router::new()
    .route("/a", get(handler_a))    // ← wrapped by the layer
    .route("/b", post(handler_b))   // ← wrapped by the layer
    .layer(my_middleware)            // ← wraps /a and /b
    .route("/c", get(handler_c))    // ← NOT wrapped (below the layer)
```

This is because Axum's builder pattern is additive — `.layer()` takes everything built _so far_ and wraps it. Routes added _after_ the layer call are outside the wrapper.

This position-dependent behavior is the foundation for selective middleware in 2.17.

## Key Takeaways

1. **`middleware::from_fn` turns a plain async function into Tower middleware.** No trait implementations, no boilerplate. The function receives `(Request, Next)` and returns `Response`. Call `next.run(request)` to pass through, or return early to reject.

2. **Middleware moves auth from handler level to router level.** One `.layer()` call protects every route in the router. Handlers go back to being pure business logic with no auth awareness.

3. **`.layer()` wraps everything above it.** Routes defined before the `.layer()` call are protected; routes after it are not. This position-dependent behavior is how Axum enables selective middleware application.

4. **Blanket middleware creates a regression.** Our middleware protects all routes equally — including GET endpoints that should remain open. This is a deliberate trade-off: simpler code (one middleware covers all) at the cost of over-restriction. We fix this in 2.17.

5. **The middleware doesn't know who the caller is — only that they have a valid key.** It's a gatekeeper, not an identity provider. In 2.16, we'll evolve it to extract and inject the caller's identity so handlers can make authorization decisions.

6. **Middleware error responses use the same `RustFlowError` type.** We call `.into_response()` directly instead of returning `Result`, but the JSON body is identical. The client sees the same structured error regardless of whether rejection happened in an extractor or middleware.
