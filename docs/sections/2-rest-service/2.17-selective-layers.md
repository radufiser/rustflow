# 2.17 - Selectively Applying Layers

## Overview

Since 2.15, every route in the task, project, and user routers requires an API key — including `GET` endpoints that should be publicly readable. The dashboard is broken (it fetches `GET /api/tasks` without a key), and any client that just wants to _read_ data has to authenticate first.

This is the regression we intentionally introduced to motivate this lesson. Now we fix it.

The solution is **router splitting**: separate each domain's routes into a **public router** (reads) and a **protected router** (writes), apply the auth middleware only to the protected router, and merge them back together. The result is exactly the access pattern we had in 2.14 — reads open, writes protected — but enforced at the router level with zero per-handler boilerplate.

### Before and After

```text
2.15/2.16 — middleware on the whole router:

  Router::new()
    .route("/",    GET(list).POST(create))     ← both protected
    .route("/{id}", GET(get).PUT(update))      ← both protected
    .layer(auth_middleware)                     ← covers everything

2.17 — split into public + protected:

  public_routes:
    .route("/",    GET(list))                  ← open
    .route("/{id}", GET(get))                  ← open

  protected_routes:
    .route("/",    POST(create))               ← protected
    .route("/{id}", PUT(update).DELETE(delete)) ← protected
    .layer(auth_middleware)

  merge(public_routes, protected_routes)       ← combined
```

The key insight: **Axum routers are composable**. You can build two routers with different middleware stacks and merge them into one. Routes at the same path but different HTTP methods coexist naturally — `GET /` from the public router and `POST /` from the protected router don't conflict.

## How Router Merging Works

In Axum, `.merge()` combines two routers into one. Routes from both routers are included, and their middleware stacks remain independent:

```rust
let public = Router::new()
    .route("/items", get(list_items));       // no middleware

let protected = Router::new()
    .route("/items", post(create_item))      // auth middleware applies
    .layer(auth_middleware);

let combined = public.merge(protected);
// GET  /items → list_items    (no auth)
// POST /items → create_item   (auth required)
```

Each router carries its own layer stack. When they're merged, a `GET /items` request goes through the public router's stack (no middleware), while a `POST /items` request goes through the protected router's stack (with auth middleware). The method determines which path the request takes.

### What If Both Routers Define the Same Method on the Same Path?

Axum panics at startup with a clear error message. Two routers merged together must not have overlapping `(method, path)` pairs. This is a compile-time (well, startup-time) safety net — you can't accidentally create conflicting routes.

```rust
// ❌ This panics: both define GET /items
let a = Router::new().route("/items", get(handler_a));
let b = Router::new().route("/items", get(handler_b));
let combined = a.merge(b); // PANIC: "Overlapping method route"
```

### `merge` vs `nest`

We've used both `.merge()` and `.nest()` in this project. Here's when to use which:

| Method | What it does | Path prefix? | Example |
|---|---|---|---|
| `.merge(router)` | Combines routes side-by-side | No — paths stay as-is | Health router merged at root |
| `.nest(prefix, router)` | Mounts routes under a prefix | Yes — prepends prefix | Task router nested at `/api/tasks` |

In this lesson we're using `.merge()` _within_ each domain module to combine public and protected route groups. The `.nest()` in `main.rs` still handles the `/api/tasks` prefix.

## Step 1: Split Task Routes

**Update** `crates/rustflow-server/src/routes/tasks.rs` — separate read and write routes into two routers, apply auth only to writes, merge them.

The handler functions are completely unchanged from 2.16. Only the `router()` function at the bottom changes.

```rust name=crates/rustflow-server/src/routes/tasks.rs
use crate::errors::RustFlowError;
use crate::extractors::{ValidatedJson, ValidatedQuery};
use crate::routes::middleware::require_api_key;
use crate::state::AppState;
use axum::extract::{Path, State};
use axum::http::StatusCode;
use axum::routing::{get, patch};
use axum::{middleware, Extension, Json, Router};
use rustflow_common::{AuthenticatedClient, CreateTask, Task, TaskFilter, TaskStatus};

// ── Read handlers (public) ──────────────────────────────────

/// GET /tasks?status=pending&priority=high
async fn list(
    State(state): State<AppState>,
    ValidatedQuery(filter): ValidatedQuery<TaskFilter>,
) -> Json<Vec<Task>> {
    let state = state.tasks.0.read().await;

    let filtered: Vec<Task> = state
        .tasks
        .iter()
        .filter(|task| filter.status.as_ref().map_or(true, |s| &task.status == s))
        .filter(|task| filter.priority.as_ref().map_or(true, |p| &task.priority == p))
        .filter(|task| {
            filter.search.as_ref().map_or(true, |s| {
                task.title.contains(s)
                    || task.description.as_ref().map_or(false, |d| d.contains(s))
            })
        })
        .cloned()
        .collect();

    Json(filtered)
}

/// GET /tasks/:id
async fn get_one(
    State(state): State<AppState>,
    Path(id): Path<u64>,
) -> Result<Json<Task>, RustFlowError> {
    let store = state.tasks.0.read().await;

    store
        .tasks
        .iter()
        .find(|task| task.id == id)
        .cloned()
        .map(Json)
        .ok_or(RustFlowError::NotFound(format!(
            "Task with id {} does not exist",
            id
        )))
}

// ── Write handlers (protected) ──────────────────────────────

/// POST /tasks
async fn create(
    Extension(client): Extension<AuthenticatedClient>,
    State(state): State<AppState>,
    ValidatedJson(payload): ValidatedJson<CreateTask>,
) -> Result<(StatusCode, Json<Task>), RustFlowError> {
    let mut store = state.tasks.0.write().await;

    if store.tasks.iter().any(|x| payload.title == x.title) {
        return Err(RustFlowError::Conflict(format!(
            "Task with title {} already exists",
            payload.title
        )));
    }

    let task = Task {
        id: store.next_id,
        title: payload.title,
        description: payload.description,
        priority: payload.priority,
        status: TaskStatus::Pending,
    };

    store.next_id += 1;
    store.tasks.push(task.clone());

    println!("[audit] Task {} created by client '{}'", task.id, client.name);

    Ok((StatusCode::CREATED, Json(task)))
}

/// DELETE /tasks/:id
async fn delete(
    Extension(client): Extension<AuthenticatedClient>,
    State(state): State<AppState>,
    Path(id): Path<u64>,
) -> Result<StatusCode, RustFlowError> {
    let mut store = state.tasks.0.write().await;
    let len_before = store.tasks.len();

    store.tasks.retain(|task| task.id != id);

    if store.tasks.len() < len_before {
        println!("[audit] Task {id} deleted by client '{}'", client.name);
        Ok(StatusCode::NO_CONTENT)
    } else {
        Err(RustFlowError::NotFound(format!(
            "Task with id {id} does not exist"
        )))
    }
}

/// PUT /tasks/:id
async fn update(
    Extension(client): Extension<AuthenticatedClient>,
    State(state): State<AppState>,
    Path(id): Path<u64>,
    ValidatedJson(payload): ValidatedJson<CreateTask>,
) -> Result<Json<Task>, RustFlowError> {
    let mut store = state.tasks.0.write().await;

    if let Some(task) = store.tasks.iter_mut().find(|task| task.id == id) {
        task.title = payload.title;
        task.description = payload.description;
        task.priority = payload.priority;
        println!("[audit] Task {id} updated by client '{}'", client.name);
        Ok(Json(task.clone()))
    } else {
        Err(RustFlowError::NotFound(format!(
            "Task with id {} does not exist",
            id
        )))
    }
}

/// PATCH /tasks/:id/status
async fn change_status(
    Extension(client): Extension<AuthenticatedClient>,
    State(state): State<AppState>,
    Path(id): Path<u64>,
    Json(payload): Json<TaskStatus>,
) -> Result<Json<Task>, RustFlowError> {
    let mut store = state.tasks.0.write().await;

    if let Some(task) = store.tasks.iter_mut().find(|task| task.id == id) {
        task.status = payload;
        println!("[audit] Task {id} status changed by client '{}'", client.name);
        Ok(Json(task.clone()))
    } else {
        Err(RustFlowError::NotFound(format!(
            "Task with id {} does not exist",
            id
        )))
    }
}

// ── Router ──────────────────────────────────────────────────

pub fn router(state: AppState) -> Router<AppState> {
    // Public routes — no authentication required
    let public = Router::new()
        .route("/", get(list))
        .route("/{id}", get(get_one));

    // Protected routes — require valid API key
    let protected = Router::new()
        .route("/", post(create))
        .route("/{id}", put(update).delete(delete))
        .route("/{id}/status", patch(change_status))
        .layer(middleware::from_fn_with_state(state, require_api_key));

    public.merge(protected)
}
```

### What Changed — Only the `router()` Function

The handler functions are **identical** to 2.16. The only change is at the bottom:

```text
// 2.16: single router, everything protected
pub fn router(state: AppState) -> Router<AppState> {
    Router::new()
        .route("/", get(list).post(create))
        .route("/{id}", get(get_one).put(update).delete(delete))
        .route("/{id}/status", patch(change_status))
        .layer(middleware::from_fn_with_state(state, require_api_key))
}

// 2.17: split into public + protected
pub fn router(state: AppState) -> Router<AppState> {
    let public = Router::new()
        .route("/", get(list))
        .route("/{id}", get(get_one));

    let protected = Router::new()
        .route("/", post(create))
        .route("/{id}", put(update).delete(delete))
        .route("/{id}/status", patch(change_status))
        .layer(middleware::from_fn_with_state(state, require_api_key));

    public.merge(protected)
}
```

Notice how the paths stay the same (`/`, `/{id}`). The split is by **HTTP method**, not by path. `GET /` goes to the public router, `POST /` goes to the protected router. Axum routes by `(method, path)` pairs, so there's no conflict.

### Import Change

One new import is needed:

```text
+ use axum::routing::post;
```

We need `post` explicitly because in 2.16 we used `get(list).post(create)` — chaining `.post()` on a `MethodRouter`. Now `create` lives in a different router, so we need `post(create)` as a standalone function call.

Similarly, `put` and `delete` are used standalone:

```rust
// Before (chained on one route):
.route("/{id}", get(get_one).put(update).delete(delete))

// After (split across routers):
// public router:
.route("/{id}", get(get_one))
// protected router:
.route("/{id}", put(update).delete(delete))
```

The full updated import block:

```rust
use axum::routing::{get, patch, post, put, delete};
```

Or you can keep `put(update).delete(delete)` as a chain on the same route in the protected router — that's fine because both `PUT` and `DELETE` need auth:

```rust
use axum::routing::{get, patch, post};
// put and delete are chained via .put() and .delete() on a MethodRouter
```

Either style works. We'll use the chaining style to keep the import list shorter.

```rust name=crates/rustflow-server/src/routes/projects.rs
use crate::errors::RustFlowError;
use crate::routes::middleware::require_api_key;
use crate::state::AppState;
use axum::extract::{Path, State};
use axum::http::StatusCode;
use axum::routing::{get, post};
use axum::{middleware, Json, Router};
use rustflow_common::{CreateProject, Project};

/// GET /projects
async fn list(State(state): State<AppState>) -> Json<Vec<Project>> {
    let store = state.projects.0.read().await;
    Json(store.projects.clone())
}

/// GET /projects/:id
async fn get_one(

    Path(id): Path<u64>,
) -> Result<Json<Project>, RustFlowError> {
    let store = state.projects.0.read().await;
    store
        .projects
        .iter()
        .find(|project| project.id == id)
        .cloned()
        .map(Json)
        .ok_or(RustFlowError::NotFound(format!(
            "Project with id {} not found",
            id
        )))
}

/// DELETE /projects/:id
async fn delete(
    State(state): State<AppState>,
    Path(id): Path<u64>,
) -> Result<StatusCode, RustFlowError> {
    let mut store = state.projects.0.write().await;
    let len_before = store.projects.len();
    store.projects.retain(|project| project.id != id);
    if store.projects.len() < len_before {
        Ok(StatusCode::NO_CONTENT)
    } else {
        Err(RustFlowError::NotFound(format!(
            "Project with id {id} does not exist"
        )))
    }
}

/// POST /projects
async fn create(
    State(state): State<AppState>,
    Json(payload): Json<CreateProject>,
) -> (StatusCode, Json<Project>) {
    let mut store = state.projects.0.write().await;
    let id = store.next_id;
    let project = Project {
        id,
        name: payload.name,
        description: payload.description,
    };
    store.next_id += 1;
    store.projects.push(project.clone());
    (StatusCode::CREATED, Json(project))
}

pub fn router(state: AppState) -> Router<AppState> {
    let public = Router::new()
        .route("/", get(list))
        .route("/{id}", get(get_one));

    let protected = Router::new()
        .route("/", post(create))
        .route("/{id}", delete(delete))
        .layer(middleware::from_fn_with_state(state, require_api_key));

    public.merge(protected)
}
```

Note: we need `use axum::routing::delete` now because `delete` is standalone in the protected router, no longer chained.

Wait — there's a naming conflict: the handler function is called `delete` and so is the routing function `axum::routing::delete`. Rust resolves this by scope, but it's cleaner to either rename the handler or import differently.

The cleanest approach is to keep the handler name and use the routing function without importing it as a bare name:

```rust
use axum::routing::{get, post};

// In the router:
let protected = Router::new()
    .route("/", post(create))
    .route("/{id}", axum::routing::delete(delete))
    .layer(middleware::from_fn_with_state(state, require_api_key));
```

Or rename the handler to `remove` to avoid the collision. Either works — use whichever you prefer.

For this lesson, we'll use the fully-qualified path to keep handler names consistent across all modules.

```rust name=crates/rustflow-server/src/routes/users.rs
use axum::routing::{get, post};

async fn list(State(state): State<AppState>) -> Json<Vec<User>> {

        id: store.next_id,
        email: payload.email,

    store.users.push(user.clone());

}

async fn delete(
    State(state): State<AppState>,
    Path(id): Path<u64>,

    let mut store = state.users.0.write().await;
    let len_before = store.users.len();
    store.users.retain(|user| user.id != id);

    if store.users.len() < len_before {
        Ok(StatusCode::NO_CONTENT)
    } else {
        Err(RustFlowError::NotFound(format!(
            "User with id {} not found",
            id
        )))
    }
}

async fn get_one(
    State(state): State<AppState>,
    Path(id): Path<u64>,
) -> Result<(StatusCode, Json<User>), RustFlowError> {
    let store = state.users.0.read().await;
    let found_user = store.users.iter().find(|user| user.id == id);

    if let Some(user) = found_user {
        Ok((StatusCode::OK, Json(user.clone())))
    } else {
        Err(RustFlowError::NotFound(format!(
            "User with id {} not found",
            id
        )))
    }
}

pub fn router(state: AppState) -> Router<AppState> {
    let public = Router::new()
        .route("/users", get(list))
        .route("/users/{id}", get(get_one));

    let protected = Router::new()
        .route("/users", post(create))
        .route("/users/{id}", axum::routing::delete(delete))
        .layer(middleware::from_fn_with_state(state, require_api_key));

    public.merge(protected)
}
```

Note: the users router uses full paths (`/users`, `/users/{id}`) rather than relative paths — that's an existing pattern in this file that predates our changes. The split works identically regardless of path style.

## The Pattern: Public + Protected Merge

This is a reusable pattern that applies to any Axum application:

```rust
pub fn router(state: AppState) -> Router<AppState> {
    // 1. Define routes that anyone can access
    let public = Router::new()
        .route("/", get(list))
        .route("/{id}", get(get_one));

    // 2. Define routes that require authentication
    let protected = Router::new()
        .route("/", post(create))
        .route("/{id}", put(update).delete(delete))
        .layer(middleware::from_fn_with_state(state, require_api_key));

    // 3. Merge — Axum routes by (method, path) so there's no conflict
    public.merge(protected)
}
```

The pattern scales to more complex scenarios:

```rust
// Three-tier access (future example)
let public = Router::new()
    .route("/", get(list));

let authenticated = Router::new()
    .route("/", post(create))
    .layer(require_auth);

let admin_only = Router::new()
    .route("/{id}", delete(remove))
    .layer(require_admin)
    .layer(require_auth);  // admin middleware checks role AFTER auth

public.merge(authenticated).merge(admin_only)
```

## Key Takeaways

1. **Router splitting is how you selectively apply middleware in Axum.** Build separate routers for routes with different middleware requirements, then `.merge()` them. Each router carries its own layer stack independently.

2. **Axum routes by `(method, path)` pairs.** `GET /tasks` and `POST /tasks` can live in different routers with different middleware. There's no conflict because they're different method+path combinations.

3. **`.merge()` panics on overlapping routes.** If two routers both define `GET /tasks`, Axum catches this at startup. This is a safety net — you can't accidentally shadow or duplicate a route.

4. **The public/protected pattern scales.** Three routes today, thirty tomorrow — any route in the `protected` sub-router is automatically covered. New endpoints can't accidentally be left unprotected.

5. **Handler functions don't change.** The split is purely structural — it changes how routes are organized, not how handlers work. The `create` handler is identical in 2.14, 2.15, 2.16, and 2.17. The auth story evolved entirely in the routing layer.

6. **The dashboard works again.** By moving reads to the public router, `GET /api/tasks` is open — the dashboard's JavaScript can fetch without credentials. This is the correct architecture: public reads, authenticated writes.

## The Full Auth Progression: 2.14 → 2.17

Looking back at the four lessons together:

| Lesson | Approach | Read access | Write access | Drawback |
|---|---|---|---|---|
| **2.14** | Per-handler extractor | 🔓 Open | 🔒 `_auth: RequireApiKey` on each handler | Manual, error-prone, verbose |
| **2.15** | Router middleware | 🔒 Protected (regression) | 🔒 Protected | Over-restriction, dashboard broken |
| **2.16** | Middleware + identity | 🔒 Protected (regression) | 🔒🪪 Protected + identity | Still over-restricted |
| **2.17** | Split routers | 🔓 Open | 🔒🪪 Protected + identity | ✅ Correct — production-ready |

Each lesson introduced one concept while revealing a problem that the next lesson solved. The final result — split routers with selective middleware and identity injection — is a production-grade auth pattern used in real Axum services.

## Exercises

1. **Add a third tier** — Create an `admin_only` sub-router that requires the `admin-key-2026` key specifically (check `client.name == "admin"`). Move the `DELETE` route into it. Now deleting tasks requires an admin key, while creating and updating works with any valid key.

2. **Protect enrichment routes** — The enrichment routes are currently open. Move them behind the auth middleware. Should they be fully protected, or should reads remain open? Make a design decision and implement it.

3. **Log unauthenticated reads** — Without requiring auth, add a second middleware to the _public_ router that logs `[access] GET /api/tasks from <ip>`. You can get the client IP from the `ConnectInfo` extension (requires enabling it on `axum::serve`). This demonstrates layering different middleware on different router segments.

4. **Test the merge conflict** — Intentionally define `GET /` in both the public and protected routers. Run the server and observe the panic message. Then fix it. This builds confidence that Axum catches routing mistakes.

5. **Optional identity for reads** — Add `Option<Extension<AuthenticatedClient>>` to the `list` handler. When a key is provided, log the client name. When no key is provided, log "anonymous". This enables a "enhanced for authenticated callers" pattern without requiring auth.

6. **Write an integration test** — Using `axum::test::TestServer` (or `reqwest` against a spawned server), write tests that verify:
   - `GET /api/tasks` returns 200 without a key
   - `POST /api/tasks` returns 401 without a key
   - `POST /api/tasks` returns 201 with a valid key
   - `POST /api/tasks` returns 403 with an invalid key

   This is the foundation for the integration testing patterns we'll build in Section 9.
