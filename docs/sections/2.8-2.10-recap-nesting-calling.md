# 2.8 - Quick Recap on State and Layers

## Overview

Before we add more complexity, let's consolidate the mental model from Sections 2.3–2.7.

### Extractors (2.3–2.4)

```text
Handler arguments = Extractors

async fn my_handler(
    State(state): State<AppState>,     ← FromRequestParts (doesn't consume body)
    Path(id): Path<u64>,               ← FromRequestParts
    Query(filter): Query<TaskFilter>,  ← FromRequestParts
    ValidatedJson(body): ...,          ← FromRequest (consumes body — must be LAST)
) -> impl IntoResponse
```

**Rules:**
- Multiple `FromRequestParts` extractors: ✅
- Only one `FromRequest` extractor (body consumer): ✅
- Body consumer must be the **last** argument: ✅
- Use `ValidatedJson<T>` for payloads that need validation: ✅

### State Evolution (2.5–2.7)

```text
2.5: Arc<AppState>              → Read-only shared state
2.6: Arc<RwLock<AppState>>      → Mutable shared state (single lock)
2.7: AppState {                 → Split state (independent locks)
       tasks: TaskState(Arc<RwLock<TaskStore>>),
       projects: ProjectState(Arc<RwLock<ProjectStore>>),
       config: AppConfig,       → No lock (immutable)
     }
```

**Choosing the right approach:**

| Scenario | Use |
|---|---|
| Data never changes after startup | `Arc<T>` or just `T: Clone` |
| Data changes, low contention | `Arc<RwLock<T>>` |
| Data changes, high contention | Split into independent `Arc<RwLock<T>>` per domain |
| Very high write contention | Consider `dashmap` or `tokio::sync::Mutex` |

### Tower Layers

Everything in Axum flows through Tower layers:

```text
Request
  │
  ├──► Layer 1 (State injection)     ← .with_state() — we've used this
  ├──► Layer 2 (Logging)             ← coming in Section 3
  ├──► Layer 3 (Auth)                ← coming in Section 2.17
  ├──► Layer 4 (Rate limiting)       ← coming in Section 2.22
  │
  ▼
Handler
```

`.with_state(state)` is syntactic sugar for adding a state injection layer. In upcoming sections, we'll add our own custom layers.

### Current Architecture

```text
                    ┌─────────────────────────────┐
                    │          AppState            │
                    │  (Clone — cheap per request) │
                    ├──────────┬──────────┬────────┤
                    │TaskState │ProjState │AppConfig│
                    │Arc<RwLock>│Arc<RwLock>│ (no lock)│
                    └──────────┴──────────┴────────┘
                          │          │         │
  GET /tasks ─────► read lock   (untouched) (untouched)
  POST /tasks ────► write lock  (untouched) (untouched)
  GET /projects ──► (untouched) read lock   (untouched)
  GET /config ────► (untouched) (untouched) direct read
```

**Key insight:** Because each domain has its own lock, creating a task doesn't block listing projects. This is the split-state pattern in action.

# 2.9 - Nested Routers with State

## Overview

In Section 2.7 we added project endpoints alongside task endpoints, but everything lives in one big `main.rs`. As RustFlow grows, this won't scale — we'll have dozens of endpoints across tasks, projects, users, health, config, etc.

Axum's **router nesting** lets us organize endpoints into separate modules, each with its own `Router`, and compose them in `main()`. The key challenge is ensuring state flows correctly through nested routers.

| `crates/rustflow-server/src/routes/mod.rs` | **Create** — module declarations |
| `crates/rustflow-server/src/routes/health.rs` | **Create** — health + config routes |
| `crates/rustflow-server/src/routes/tasks.rs` | **Create** — task CRUD routes |
| `crates/rustflow-server/src/routes/projects.rs` | **Create** — project CRUD routes |
| `crates/rustflow-server/src/main.rs` | **Update** — compose nested routers |

## How Nesting Works

```text
Router::new()
    .route("/", get(root))                          → GET /
    .merge(health::router())                        → GET /health, GET /config
    .nest("/api/tasks", tasks::router())            → GET /api/tasks, POST /api/tasks, etc.
    .nest("/api/projects", projects::router())      → GET /api/projects, POST /api/projects, etc.
    .with_state(state)
```

There are two ways to compose routers:

| Method | Behavior |
|---|---|
| `.merge(router)` | Combines routes at the same level — no prefix added |
| `.nest("/prefix", router)` | Adds a path prefix to all routes in the nested router |

We'll use `.merge()` for health/config (they live at root level) and `.nest()` for domain routes (prefixed under `/api/`).

### State and Nested Routers

**Critical rule:** When you call `.with_state(state)` on the outer router, it provides state to all merged and nested routers — **as long as their type signature matches**.

Each route module returns `Router<AppState>` (a router that *expects* `AppState` but doesn't have it yet). The outer router provides it via `.with_state()`.

## Step 4: Create the Task Routes

**Create** `crates/rustflow-server/src/routes/tasks.rs`:

```rust name=crates/rustflow-server/src/routes/tasks.rs
use axum::{
    extract::{Json, Path, Query, State},
    http::StatusCode,
    routing::get,
    Router,
};
use rustflow_common::{CreateTask, Task, TaskFilter, TaskStatus};

use crate::extractors::ValidatedJson;
use crate::state::AppState;

/// GET /api/tasks?status=done&priority=high
async fn list(
    State(state): State<AppState>,
    Query(filter): Query<TaskFilter>,
) -> Json<Vec<Task>> {
    let store = state.tasks.0.read().await;

    let filtered: Vec<Task> = store
        .tasks
        .iter()
        .filter(|t| filter.status.as_ref().map_or(true, |s| &t.status == s))
        .filter(|t| filter.priority.as_ref().map_or(true, |p| &t.priority == p))
        .cloned()
        .collect();

    Json(filtered)
}

/// GET /api/tasks/:id
async fn get_one(
    State(state): State<AppState>,
    Path(id): Path<u64>,
) -> Result<Json<Task>, StatusCode> {
    let store = state.tasks.0.read().await;

    store
        .tasks
        .iter()
        .find(|t| t.id == id)
        .cloned()
        .map(Json)
        .ok_or(StatusCode::NOT_FOUND)
}

/// POST /api/tasks
async fn create(
    State(state): State<AppState>,
    ValidatedJson(payload): ValidatedJson<CreateTask>,
) -> (StatusCode, Json<Task>) {
    let mut store = state.tasks.0.write().await;

    let task = Task {
        id: store.next_id,
        title: payload.title,
        description: payload.description,
        priority: payload.priority,
        status: TaskStatus::Pending,
    };

    store.next_id += 1;
    store.tasks.push(task.clone());

    (StatusCode::CREATED, Json(task))
}

/// DELETE /api/tasks/:id
async fn delete(
    State(state): State<AppState>,
    Path(id): Path<u64>,
) -> StatusCode {
    let mut store = state.tasks.0.write().await;

    let len_before = store.tasks.len();
    store.tasks.retain(|t| t.id != id);

    if store.tasks.len() < len_before {
        StatusCode::NO_CONTENT
    } else {
        StatusCode::NOT_FOUND
    }
}

/// Build the tasks router.
///
/// Mounted with `.nest("/api/tasks", ...)` in main so these become:
///   GET    /api/tasks
///   POST   /api/tasks
///   GET    /api/tasks/:id
///   DELETE /api/tasks/:id
pub fn router() -> Router<AppState> {
    Router::new()
        .route("/", get(list).post(create))
        .route("/{id}", get(get_one).delete(delete))
}
```

```rust name=crates/rustflow-server/src/main.rs
use axum::{routing::get, Router};
use rustflow_common::{APP_NAME, APP_VERSION};
use tokio::net::TcpListener;

mod extractors;
mod routes;
mod state;

use state::AppState;

/// Root endpoint — simple liveness check.
async fn root() -> &'static str {
    "RustFlow is running"
}

#[tokio::main]
async fn main() {
    let state = AppState::new();

    let app = Router::new()
        // Root liveness
        .route("/", get(root))
        // Health & config — merged at root level (no prefix)
        .merge(routes::health::router())
        // Domain routes — nested under /api/*
        .nest("/api/tasks", routes::tasks::router())
        .nest("/api/projects", routes::projects::router())
        // Provide state to ALL routes (merged and nested)
        .with_state(state);

    let addr = "0.0.0.0:3000";
    let listener = TcpListener::bind(addr)
        .await
        .expect("Failed to bind to address");

    println!("{} v{} listening on {}", APP_NAME, APP_VERSION, addr);

    axum::serve(listener, app)
        .await
        .expect("Server error");
}
```

### How State Flows Through Nested Routers

```text
main()
  │
  ├── AppState::new()
  │
  ├── Router::new()
  │     ├── .route("/", get(root))              ← no state needed
  │     ├── .merge(health::router())            ← Router<AppState>: needs state
  │     ├── .nest("/api/tasks", tasks::router())    ← Router<AppState>: needs state
  │     ├── .nest("/api/projects", projects::router()) ← Router<AppState>: needs state
  │     └── .with_state(state)                  ← provides AppState to ALL of the above
  │                                                converts Router<AppState> → Router<()>
  ▼
  Router<()>  ← fully resolved, ready to serve
```

The type parameter on `Router<S>` represents "what state this router still needs." When you call `.with_state(state)`, it resolves `Router<AppState>` → `Router<()>` (no state needed — it's been provided).

**If the types don't match, you get a compile error.** This is one of Axum's great strengths — mismatched state is caught at build time, not at runtime.

# 2.10 - Calling Other Services

## Overview

RustFlow doesn't exist in isolation. In a real service-oriented architecture, services call each other constantly — fetching user profiles from an identity service, sending notifications, checking permissions, etc.

In this lesson, we add an endpoint that calls an external HTTP API from within a RustFlow handler. We'll use the [`reqwest`](https://crates.io/crates/reqwest) crate (the de facto Rust HTTP client) and learn how to manage the HTTP client as shared state.

## Why Not Just Create a `reqwest::Client` Per Request?

Each `reqwest::Client` holds a connection pool, TLS configuration, and other expensive resources. Creating one per request wastes all of that. Instead, we create a **single client at startup** and share it through state — just like we share `TaskState` and `ProjectState`.

```text
❌ Bad: new Client per request
  Request 1 → Client::new() → DNS + TLS handshake → response → drop
  Request 2 → Client::new() → DNS + TLS handshake → response → drop

✅ Good: shared Client
  Startup   → Client::new() (once)
  Request 1 → reuse connection pool → response
  Request 2 → reuse connection pool → response
```

```rust name=crates/rustflow-server/src/state.rs
use rustflow_common::{AppConfig, Priority, Project, Task, TaskStatus};
use std::sync::Arc;
use tokio::sync::RwLock;

// ── Task State ──────────────────────────────────────────────

#[derive(Clone)]
pub struct TaskState(pub Arc<RwLock<TaskStore>>);

pub struct TaskStore {
    pub tasks: Vec<Task>,
    pub next_id: u64,
}

impl TaskStore {
    pub fn new() -> Self {
        let tasks = vec![
            Task {
                id: 1,
                title: "Set up workspace".into(),
                description: Some("Initialize the Cargo workspace".into()),
                priority: Priority::High,
                status: TaskStatus::Done,
            },
            Task {
                id: 2,
                title: "Add Axum".into(),
                description: Some("Create the HTTP server".into()),
                priority: Priority::High,
                status: TaskStatus::InProgress,
            },
            Task {
                id: 3,
                title: "Write extractors lesson".into(),
                description: None,
                priority: Priority::Medium,
                status: TaskStatus::Pending,
            },
        ];
        let next_id = tasks.len() as u64 + 1;
        Self { tasks, next_id }
    }
}

impl TaskState {
    pub fn new() -> Self {
        Self(Arc::new(RwLock::new(TaskStore::new())))
    }
}

// ── Project State ───────────────────────────────────────────

#[derive(Clone)]
pub struct ProjectState(pub Arc<RwLock<ProjectStore>>);

pub struct ProjectStore {
    pub projects: Vec<Project>,
    pub next_id: u64,
}

impl ProjectStore {
    pub fn new() -> Self {
        Self {
            projects: vec![Project {
                id: 1,
                name: "RustFlow Development".into(),
                description: Some("Building the RustFlow service".into()),
            }],
            next_id: 2,
        }
    }
}

impl ProjectState {
    pub fn new() -> Self {
        Self(Arc::new(RwLock::new(ProjectStore::new())))
    }
}

// ── Combined State ──────────────────────────────────────────

/// The combined application state that Axum will manage.
/// Each component is independently clonable and lockable.
#[derive(Clone)]
pub struct AppState {
    pub tasks: TaskState,
    pub projects: ProjectState,
    pub config: AppConfig,
    /// Shared HTTP client for calling external services.
    /// `reqwest::Client` uses `Arc` internally, so cloning is cheap.
    pub http_client: reqwest::Client,
}

impl AppState {
    pub fn new() -> Self {
        Self {
            tasks: TaskState::new(),
            projects: ProjectState::new(),
            config: AppConfig::default(),
            http_client: reqwest::Client::new(),
        }
    }
}
```

### Why does `reqwest::Client` not need `Arc`?

`reqwest::Client` already uses `Arc` internally. Calling `.clone()` on it is cheap — it just increments a reference count. This is documented in the reqwest docs and is a common pattern for Rust libraries that manage expensive resources.

```rust name=crates/rustflow-server/src/routes/enrichment.rs
use axum::{
    extract::{Json, Path, State},
    http::StatusCode,
    response::{IntoResponse, Response},
    routing::get,
    Router,
};

use crate::state::AppState;

/// A user fetched from the external JSONPlaceholder API.
#[derive(Debug, serde::Deserialize, serde::Serialize)]
struct ExternalUser {
    id: u64,
    name: String,
    email: String,
    username: String,
}

/// An enriched task that includes both RustFlow task data
/// and external user data.
#[derive(Debug, serde::Serialize)]
struct EnrichedTask {
    id: u64,
    title: String,
    description: Option<String>,
    priority: String,
    status: String,
    assigned_to: ExternalUser,
}

/// Errors that can occur when enriching a task.
enum EnrichmentError {
    TaskNotFound,
    ExternalServiceError(String),
}

impl IntoResponse for EnrichmentError {
    fn into_response(self) -> Response {
        match self {
            Self::TaskNotFound => {
                (StatusCode::NOT_FOUND, "Task not found").into_response()
            }
            Self::ExternalServiceError(msg) => {
                (StatusCode::BAD_GATEWAY, format!("External service error: {}", msg))
                    .into_response()
            }
        }
    }
}

/// GET /api/enrichment/tasks/:task_id/user/:user_id
///
/// Fetches a task from local state and a user from an external API,
/// then combines them into an enriched response.
///
/// This demonstrates:
/// 1. Accessing local state (task store)
/// 2. Making an outbound HTTP call (reqwest)
/// 3. Combining data from multiple sources
/// 4. Handling errors from external services
async fn enrich_task(
    State(state): State<AppState>,
    Path((task_id, user_id)): Path<(u64, u64)>,
) -> Result<Json<EnrichedTask>, EnrichmentError> {
    // Step 1: Find the task in local state
    let task = {
        let store = state.tasks.0.read().await;
        store
            .tasks
            .iter()
            .find(|t| t.id == task_id)
            .cloned()
            .ok_or(EnrichmentError::TaskNotFound)?
    };
    // Note: The read lock is dropped here (end of block).
    // We don't hold it across the HTTP call — that would block
    // other readers for the duration of the network request.

    // Step 2: Fetch user from external service
    let url = format!("https://jsonplaceholder.typicode.com/users/{}", user_id);

    let user: ExternalUser = state
        .http_client
        .get(&url)
        .send()
        .await
        .map_err(|e| EnrichmentError::ExternalServiceError(e.to_string()))?
        .error_for_status()
        .map_err(|e| EnrichmentError::ExternalServiceError(e.to_string()))?
        .json()
        .await
        .map_err(|e| EnrichmentError::ExternalServiceError(e.to_string()))?;

    // Step 3: Combine into enriched response
    let enriched = EnrichedTask {
        id: task.id,
        title: task.title,
        description: task.description,
        priority: format!("{:?}", task.priority),
        status: format!("{:?}", task.status),
        assigned_to: user,
    };

    Ok(Json(enriched))
}

/// GET /api/enrichment/external-users
///
/// A simpler example: just proxy an external API call and return the result.
/// Useful for testing that the HTTP client works.
async fn list_external_users(
    State(state): State<AppState>,
) -> Result<Json<Vec<ExternalUser>>, EnrichmentError> {
    let users: Vec<ExternalUser> = state
        .http_client
        .get("https://jsonplaceholder.typicode.com/users")
        .send()
        .await
        .map_err(|e| EnrichmentError::ExternalServiceError(e.to_string()))?
        .json()
        .await
        .map_err(|e| EnrichmentError::ExternalServiceError(e.to_string()))?;

    Ok(Json(users))
}

/// Build the enrichment router.
///
/// Mounted with `.nest("/api/enrichment", ...)` in main so these become:
///   GET /api/enrichment/tasks/:task_id/user/:user_id
///   GET /api/enrichment/external-users
pub fn router() -> Router<AppState> {
    Router::new()
        .route("/tasks/{task_id}/user/{user_id}", get(enrich_task))
        .route("/external-users", get(list_external_users))
}
```

### Key Pattern: Don't Hold Locks Across `.await`

Notice how we scope the read lock:

```rust
// ✅ GOOD — lock is dropped before the HTTP call
let task = {
    let store = state.tasks.0.read().await;
    store.tasks.iter().find(|t| t.id == task_id).cloned()
};
// lock dropped here

// Now safe to do a slow network call
let user = state.http_client.get(&url).send().await...;
```

If we held the lock across the HTTP call:

```rust
// ❌ BAD — lock held during slow network I/O
let store = state.tasks.0.read().await;
let task = store.tasks.iter().find(|t| t.id == task_id).cloned();
// lock is STILL held here!
let user = state.http_client.get(&url).send().await...;
// lock finally dropped when `store` goes out of scope
```

This would block ALL other task handlers (even readers) for the entire duration of the network request — potentially seconds.

### Error Handling: `BAD_GATEWAY` for Upstream Failures

We return `502 Bad Gateway` when the external service fails. This is the correct HTTP status: it signals to the caller that RustFlow itself is fine, but an upstream dependency failed.

## Key Takeaways

1. **Share the HTTP client** — create `reqwest::Client` once and put it in state. It uses `Arc` internally, so cloning is free.
2. **Don't hold locks across `.await`** — scope your lock acquisition with blocks `{ let store = ...; ... }` so the lock is dropped before any network calls.
3. **Use appropriate HTTP status codes** — `502 Bad Gateway` for upstream failures, `404` for local not-found.
4. **Deserialize directly** — `reqwest` can deserialize JSON responses into your types with `.json::<T>().await`.
