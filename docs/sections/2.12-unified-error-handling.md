# 2.12 - Unified Error Handling

## Overview

Right now RustFlow's error handling works — but it's **inconsistent**. Some handlers return a bare `StatusCode` with an empty body, others return plain text, and our custom extractors return structured JSON. A client consuming the API has no predictable error format to rely on.

In this lesson we build a **unified `RustFlowError` type** that every handler uses. Every error response will be structured JSON with the same shape, making the API predictable and debuggable.

Along the way we'll solidify our understanding of Axum's `IntoResponse` trait — the mechanism that makes all of this work.

## The Problem: Inconsistent Error Responses

Let's look at what RustFlow currently returns when things go wrong:

```text
GET  /api/tasks/999
  → 404  (empty body)                           ← bare StatusCode

DELETE /api/tasks/999
  → 404  (empty body)                           ← bare StatusCode

GET  /api/enrichment/tasks/999/user/1
  → 404  "Task not found"                       ← plain text

GET  /api/enrichment/tasks/1/user/99999
  → 502  "External service error: ..."          ← plain text

POST /api/tasks  {"title": ""}
  → 422  {"error":"Validation failed", ...}     ← structured JSON
```

A client would need **three different error-parsing strategies** for a single API. That's unacceptable in production.

### What We Want

Every error should return the same JSON shape:

```json
{
  "error": "Not found",
  "details": "Task with id 999 does not exist"
}
```

```json
{
  "error": "Validation failed",
  "details": {
    "title": ["Title must be between 1 and 100 characters"]
  }
}
```

Same outer structure (`error` + `details`), predictable status codes, always JSON.

## How `IntoResponse` Works

Before we build the unified error type, let's understand the trait that powers Axum's response system.

Every Axum handler must return something that implements `IntoResponse`. This trait has one method:

```rust
pub trait IntoResponse {
    fn into_response(self) -> Response;
}
```

Axum provides `IntoResponse` implementations for many common types out of the box:

| Return type | Status code | Body |
|---|---|---|
| `String` | 200 OK | The string |
| `&str` | 200 OK | The string |
| `Json<T>` | 200 OK | Serialized JSON |
| `StatusCode` | That code | Empty body |
| `(StatusCode, String)` | That code | The string |
| `(StatusCode, Json<T>)` | That code | Serialized JSON |
| `Result<T, E>` where both impl `IntoResponse` | `T`'s code on `Ok`, `E`'s code on `Err` | Respective body |

This is how our handlers already work without us thinking about it:

```rust
// Returns 200 + JSON body — Json<T> implements IntoResponse
async fn list(...) -> Json<Vec<Task>> { ... }

// Returns 201 + JSON body — (StatusCode, Json<T>) implements IntoResponse
async fn create(...) -> (StatusCode, Json<Task>) { ... }

// Returns 200 + JSON on Ok, or the bare StatusCode on Err
async fn get_one(...) -> Result<Json<Task>, StatusCode> { ... }
```

The key insight: **if you implement `IntoResponse` for your own error type, you control exactly what the client sees when something goes wrong.**

We already did this for `EnrichmentError` in 2.11 and for `ValidatedJsonError` in 2.4 — now we're going to unify them into one type.

> **Why not change `extractors.rs`?**
> `ValidatedJsonError` and `ValidatedQueryError` are tightly coupled to the extraction layer — they fire *before* your handler code runs. They already return structured JSON with proper status codes. Merging them into `RustFlowError` would blur the boundary between "request couldn't be parsed" and "request was parsed but handler logic failed." Keep extraction errors and handler errors separate.

## Step 1: Create the Unified Error Type

**Create** `crates/rustflow-server/src/errors.rs`:

```rust name=crates/rustflow-server/src/errors.rs
use axum::{
    http::StatusCode,
    response::{IntoResponse, Response},
    Json,
};

// ── The unified error type ──────────────────────────────────

/// A single error type for all RustFlow handler errors.
///
/// Every variant maps to a specific HTTP status code and produces
/// a consistent JSON response body:
///
/// ```json
/// {
///   "error": "Short description",
///   "details": "More context about what went wrong"
/// }
/// ```
#[derive(Debug)]
pub enum RustFlowError {
    /// 404 — the requested resource does not exist.
    NotFound(String),

    /// 400 — the client sent something we can't process.
    BadRequest(String),

    /// 422 — payload parsed but failed business-rule validation.
    UnprocessableEntity(String),

    /// 502 — an upstream / external service call failed.
    ExternalService(String),

    /// 500 — something unexpected went wrong on our side.
    Internal(String),
}

// ── IntoResponse ────────────────────────────────────────────

impl IntoResponse for RustFlowError {
    fn into_response(self) -> Response {
        let (status, error, details) = match self {
            Self::NotFound(msg) => (
                StatusCode::NOT_FOUND,
                "Not found",
                msg,
            ),
            Self::BadRequest(msg) => (
                StatusCode::BAD_REQUEST,
                "Bad request",
                msg,
            ),
            Self::UnprocessableEntity(msg) => (
                StatusCode::UNPROCESSABLE_ENTITY,
                "Validation failed",
                msg,
            ),
            Self::ExternalService(msg) => (
                StatusCode::BAD_GATEWAY,
                "External service error",
                msg,
            ),
            Self::Internal(msg) => (
                StatusCode::INTERNAL_SERVER_ERROR,
                "Internal server error",
                msg,
            ),
        };

        let body = serde_json::json!({
            "error": error,
            "details": details,
        });

        (status, Json(body)).into_response()
    }
}

// ── Display ─────────────────────────────────────────────────

impl std::fmt::Display for RustFlowError {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        match self {
            Self::NotFound(msg)            => write!(f, "Not found: {msg}"),
            Self::BadRequest(msg)          => write!(f, "Bad request: {msg}"),
            Self::UnprocessableEntity(msg) => write!(f, "Validation failed: {msg}"),
            Self::ExternalService(msg)     => write!(f, "External service error: {msg}"),
            Self::Internal(msg)            => write!(f, "Internal error: {msg}"),
        }
    }
}
```

### Design Decisions

**Why an enum and not a struct?**

Each variant carries its own semantics (status code + error label). With a struct you'd need to pass the status code manually every time — easy to get wrong:

```rust
// ❌ Struct approach — easy to mismatch status and message
RustFlowError { status: StatusCode::NOT_FOUND, message: "Bad gateway".into() }

// ✅ Enum approach — variant name IS the semantics
RustFlowError::NotFound("Task with id 999 does not exist".into())
```

**Why `String` and not `&str`?**

Error details are often dynamic (containing IDs, field names, upstream messages). Owned `String` avoids lifetime gymnastics in async handlers where references to temporary data would not compile.

**Why implement `Display`?**

It's a Rust best practice for error types. It enables `.to_string()`, logging with `tracing::error!("{err}")`, and chaining with other error libraries later (e.g., `anyhow`, `thiserror`).

**Why is `IntoResponse` a separate impl block?**

Convention. `IntoResponse` is Axum-specific glue. Keeping it visually separate from the type definition makes it clear which part is "our domain" and which part is "framework integration." When you later add `thiserror` or `tracing` integration, each concern gets its own block.

## Step 3: Refactor Task Routes

**Update** `crates/rustflow-server/src/routes/tasks.rs`

The changes:
- Import `RustFlowError` instead of (or in addition to) `StatusCode`
- `get_one` returns `Result<Json<Task>, RustFlowError>` instead of `Result<Json<Task>, StatusCode>`
- `delete` returns `Result<StatusCode, RustFlowError>` — success is `204 No Content`, failure is a structured `404`
- `update` and `change_status` return `Result<Json<Task>, RustFlowError>`
- `create` and `list` are **unchanged** — success responses don't need `RustFlowError`

```rust name=crates/rustflow-server/src/routes/tasks.rs
use crate::errors::RustFlowError;
use crate::extractors::{ValidatedJson, ValidatedQuery};
use crate::state::AppState;
use axum::extract::{Path, State};
use axum::http::StatusCode;
use axum::routing::{get, patch};
use axum::{Json, Router};
use rustflow_common::{CreateTask, Task, TaskFilter, TaskStatus};

/// GET /tasks?status=pending&priority=high
///
/// Unchanged — list always succeeds (empty list is not an error).
async fn list(
    State(state): State<AppState>,
    ValidatedQuery(filter): ValidatedQuery<TaskFilter>,
) -> Json<Vec<Task>> {
    let state = state.tasks.0.read().await;

    let filtered: Vec<Task> = state
        .tasks
        .iter()
        .filter(|task| filter.status.as_ref().map_or(true, |s| &task.status == s))
        .filter(|task| filter.priority.as_ref().map_or(true, |p| &task.priority == p))
        .filter(|task| {
            filter.search.as_ref().map_or(true, |s| {
                task.title.contains(s)
                    || task.description.as_ref().map_or(false, |d| d.contains(s))
            })
        })
        .cloned()
        .collect();

    Json(filtered)
}

/// GET /tasks/:id
///
/// BEFORE: Result<Json<Task>, StatusCode>        → empty 404
/// AFTER:  Result<Json<Task>, RustFlowError>     → {"error":"Not found","details":"..."}
async fn get_one(
    State(state): State<AppState>,
    Path(id): Path<u64>,
) -> Result<Json<Task>, RustFlowError> {
    let store = state.tasks.0.read().await;

    store
        .tasks
        .iter()
        .find(|task| task.id == id)
        .cloned()
        .map(Json)
        .ok_or(RustFlowError::NotFound(
            format!("Task with id {id} does not exist"),
        ))
}

/// POST /tasks
///
/// Unchanged — creation always succeeds once validation passes.
async fn create(
    State(state): State<AppState>,
    ValidatedJson(payload): ValidatedJson<CreateTask>,
) -> (StatusCode, Json<Task>) {
    let mut store = state.tasks.0.write().await;

    let task = Task {
        id: store.next_id,
        title: payload.title,
        description: payload.description,
        priority: payload.priority,
        status: TaskStatus::Pending,
    };

    store.next_id += 1;
    store.tasks.push(task.clone());

    (StatusCode::CREATED, Json(task))
}

/// DELETE /tasks/:id
///
/// BEFORE: StatusCode                            → empty 404
/// AFTER:  Result<StatusCode, RustFlowError>     → 204 on success, structured 404 on miss
async fn delete(
    State(state): State<AppState>,
    Path(id): Path<u64>,
) -> Result<StatusCode, RustFlowError> {
    let mut store = state.tasks.0.write().await;
    let len_before = store.tasks.len();

    store.tasks.retain(|task| task.id != id);

    if store.tasks.len() < len_before {
        Ok(StatusCode::NO_CONTENT)
    } else {
        Err(RustFlowError::NotFound(
            format!("Task with id {id} does not exist"),
        ))
    }
}

/// PUT /tasks/:id
///
/// BEFORE: Result<Json<Task>, StatusCode>        → empty 404
/// AFTER:  Result<Json<Task>, RustFlowError>     → structured 404
async fn update(
    State(state): State<AppState>,
    Path(id): Path<u64>,
    ValidatedJson(payload): ValidatedJson<CreateTask>,
) -> Result<Json<Task>, RustFlowError> {
    let mut store = state.tasks.0.write().await;

    if let Some(task) = store.tasks.iter_mut().find(|task| task.id == id) {
        task.title = payload.title;
        task.description = payload.description;
        task.priority = payload.priority;
        Ok(Json(task.clone()))
    } else {
        Err(RustFlowError::NotFound(
            format!("Task with id {id} does not exist"),
        ))
    }
}

/// PATCH /tasks/:id/status
///
/// BEFORE: Result<Json<Task>, StatusCode>        → empty 404
/// AFTER:  Result<Json<Task>, RustFlowError>     → structured 404
async fn change_status(
    State(state): State<AppState>,
    Path(id): Path<u64>,
    Json(payload): Json<TaskStatus>,
) -> Result<Json<Task>, RustFlowError> {
    let mut store = state.tasks.0.write().await;

    if let Some(task) = store.tasks.iter_mut().find(|task| task.id == id) {
        task.status = payload;
        Ok(Json(task.clone()))
    } else {
        Err(RustFlowError::NotFound(
            format!("Task with id {id} does not exist"),
        ))
    }
}

pub fn router() -> Router<AppState> {
    Router::new()
        .route("/", get(list).post(create))
        .route("/{id}", get(get_one).put(update).delete(delete))
        .route("/{id}/status", patch(change_status))
}
```

### What Changed — Before vs After

```text
BEFORE (bare StatusCode):

  GET /api/tasks/999
  → 404
  → (empty body)

AFTER (RustFlowError):

  GET /api/tasks/999
  → 404
  → {"error": "Not found", "details": "Task with id 999 does not exist"}
```

The status code is the same. The difference is the client now gets **actionable context** instead of silence.

## Step 5: Refactor Enrichment Routes

**Update** `crates/rustflow-server/src/routes/enrichment.rs` — replace the local `EnrichmentError` enum with `RustFlowError`.

```rust name=crates/rustflow-server/src/routes/enrichment.rs
use crate::errors::RustFlowError;
use crate::state::AppState;
use axum::extract::{Path, State};
use axum::{routing::get, Json, Router};

// ── Types ───────────────────────────────────────────────────

/// A user fetched from the external JSONPlaceholder API.
#[derive(Debug, serde::Serialize, serde::Deserialize)]
struct ExternalUser {
    id: u64,
    name: String,
    email: String,
    username: String,
}

/// An enriched task that includes both RustFlow task data
/// and external user data.
#[derive(Debug, serde::Serialize, serde::Deserialize)]
struct EnrichedTask {
    id: u64,
    title: String,
    description: Option<String>,
    priority: String,
    status: String,
    assign_to: ExternalUser,
}

// ── Handlers ────────────────────────────────────────────────

/// GET /api/enrichment/tasks/:task_id/user/:user_id
///
/// Fetches a task from local state and a user from an external API,
/// then combines them into an enriched response.
async fn enrich_task(
    State(state): State<AppState>,
    Path((task_id, user_id)): Path<(u64, u64)>,
) -> Result<Json<EnrichedTask>, RustFlowError> {
    // Step 1: Find the task in local state (lock scoped!)
    let task = {
        let store = state.tasks.0.read().await;
        store
            .tasks
            .iter()
            .find(|t| t.id == task_id)
            .cloned()
            .ok_or(RustFlowError::NotFound(
                format!("Task with id {task_id} does not exist"),
            ))?
    };
    // <- read lock is dropped here (end of the block)

    // Step 2: Fetch user from external service
    let url = format!("https://jsonplaceholder.typicode.com/users/{user_id}");

    let user: ExternalUser = state
        .http_client
        .get(&url)
        .send()
        .await
        .map_err(|e| RustFlowError::ExternalService(e.to_string()))?
        .error_for_status()
        .map_err(|e| RustFlowError::ExternalService(e.to_string()))?
        .json()
        .await
        .map_err(|e| RustFlowError::ExternalService(e.to_string()))?;

    // Step 3: Combine into enriched response
    let enriched = EnrichedTask {
        id: task_id,
        title: task.title,
        description: task.description,
        priority: format!("{:?}", task.priority),
        status: format!("{:?}", task.status),
        assign_to: user,
    };

    Ok(Json(enriched))
}

/// GET /api/enrichment/external-users
///
/// A simpler example: just proxy an external API call and return the result.
async fn list_external_users(
    State(state): State<AppState>,
) -> Result<Json<Vec<ExternalUser>>, RustFlowError> {
    let users: Vec<ExternalUser> = state
        .http_client
        .get("https://jsonplaceholder.typicode.com/users")
        .send()
        .await
        .map_err(|e| RustFlowError::ExternalService(e.to_string()))?
        .json()
        .await
        .map_err(|e| RustFlowError::ExternalService(e.to_string()))?;

    Ok(Json(users))
}

pub fn router() -> Router<AppState> {
    Router::new()
        .route("/tasks/{task_id}/user/{user_id}", get(enrich_task))
        .route("/external-users", get(list_external_users))
}
```

### What We Removed

The entire `EnrichmentError` enum and its `IntoResponse` impl are gone. `enrichment.rs` no longer needs `use axum::http::StatusCode` or `use axum::response::{IntoResponse, Response}` — all of that now lives in one place: `errors.rs`.

```text
BEFORE (EnrichmentError):                    AFTER (RustFlowError):

enrichment.rs                                enrichment.rs
├── struct ExternalUser                      ├── struct ExternalUser
├── struct EnrichedTask                      ├── struct EnrichedTask
├── enum EnrichmentError          ← gone     ├── (uses crate::errors::RustFlowError)
│   ├── TaskNotFound                         │
│   └── ExternalServiceError                 │
├── impl IntoResponse             ← gone     │
│     for EnrichmentError                    │
├── fn enrich_task                           ├── fn enrich_task
├── fn list_external_users                   ├── fn list_external_users
└── fn router()                              └── fn router()
```

Every new module you add in the future just imports `RustFlowError` — no more writing per-module error types.

## Error Response Map After 2.12

Here's the complete picture of who produces errors and what they look like:

```text
Source               Status   Body shape                                         Layer
───────────────────  ───────  ─────────────────────────────────────────────────   ──────────
RustFlowError        4xx/5xx  {"error": "...", "details": "..."}                 Handler
ValidatedJsonError   422      {"error": "Validation failed", "details": {...}}   Extractor
ValidatedQueryError  422      {"error": "Validation failed", "details": {...}}   Extractor
Axum built-in        400      Axum's built-in plain text (e.g. bad path param)   Framework
```

All **handler** errors now go through `RustFlowError`. **Extractor** errors remain in the extraction layer (already structured from 2.4). The only "uncontrolled" errors are Axum's built-in rejections (e.g., unparseable path parameters) — we can address those with a fallback handler in a later section.

## Key Takeaways

1. **`IntoResponse` is the trait** that controls what Axum sends back to the client. Implement it on your own type to control status codes, headers, and response bodies.

2. **One error type per service** — a single `RustFlowError` enum replaces scattered bare `StatusCode` returns and per-module error types. One place to add variants, one place to format responses, one place to integrate with logging later.

3. **Enums encode semantics** — `RustFlowError::NotFound(msg)` is self-documenting. You can't accidentally pair a 404 status with a "Bad gateway" message like you could with a struct.

4. **Keep extractor errors separate** — extraction happens *before* your handler runs. Let extractors handle their own errors (`ValidatedJsonError`, `ValidatedQueryError`); use `RustFlowError` for everything inside handler logic. Two layers, two error types, clean boundary.

5. **Consistent error shape** — clients can write one error parser for your entire API. This matters enormously for frontend teams, SDK generation, and automated monitoring that parses error responses.

6. **Success responses are untouched** — `RustFlowError` only appears in the `Err` side of `Result`. Your `(StatusCode::CREATED, Json(task))` and `Json<Vec<Task>>` returns don't change at all.
